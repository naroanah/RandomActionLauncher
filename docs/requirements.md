# macOS 随机行动启动器需求文档

版本：1.0  
文档对象：AI 开发代理  
产品阶段：个人自用 MVP  
需求状态：已确认

## 1 AI 执行约定

本文是实现该应用的需求基线。AI 开发代理应遵守以下规则：

1. 标有“必须”的内容属于 MVP 验收条件，不得擅自删减。
2. 标有“实现默认值”的内容尚未经过单独产品决策，但为避免阻塞开发，首版按本文给定值实现。
3. 若现有代码仓库与本文冲突，应先说明冲突及影响，再修改实现方案，不得静默改变产品行为。
4. 不得把“明确不做”的能力以顺手优化、预留入口或隐藏实验功能的形式加入 MVP。
5. 应优先完成可运行的端到端闭环，再处理视觉润色。
6. 所有用户数据必须留在本机。禁止接入账号、云服务、遥测、广告或第三方分析 SDK。

## 2 产品定义

### 2.1 一句话说明

这是一款 macOS 本地菜单栏应用。用户预先添加可立即开始的文件、文件夹或视频；当用户不知道接下来做什么时，应用按权重随机给出一个候选项，并可通过系统默认应用直接打开。

### 2.2 核心问题

用户拥有许多可以推进的项目或可以消费的本地内容，但在空档或走神时容易停在“接下来做什么”的选择上。应用通过随机给出一个具体入口，缩短从空白状态到开始行动的距离。

### 2.3 产品承诺

产品承诺快速打破空白并给出下一候选，不承诺替用户强制做决定。用户可以无限重抽，最终决定权始终属于用户。

### 2.4 首位用户

MVP 只服务应用作者本人。首版不需要处理多用户、团队协作、公共发布或商业化需求。

## 3 目标与非目标

### 3.1 MVP 目标

- 用户可以逐项添加本地文件、文件夹和视频，形成个人行动池。
- 用户可以从菜单栏快速发起一次随机抽取。
- 应用按项目权重随机选择一个当前可用的项目。
- 用户可以打开结果，也可以无限重抽。
- 用户可以维护项目的名称、备注、权重和状态。
- 应用可以避免最近抽中过的项目在 24 小时内再次出现。
- 应用只访问用户明确授权的本地内容，并把全部数据保存在本机。

### 3.2 明确不做

MVP 不得包含以下能力：

- 自动扫描整个文件夹、磁盘或用户目录。
- 根据目录内容自动生成项目。
- 内置视频播放器、音频播放器、PDF 阅读器或文档编辑器。
- 账号、登录、云同步、多人协作或跨设备同步。
- 多内容池、标签系统、场景筛选或复杂搜索。
- 提醒、通知、连续打卡、积分、排行榜或其他游戏化系统。
- AI 内容理解、AI 推荐、AI 项目拆分或联网推理。
- Finder 扩展、系统分享扩展或右键菜单集成。
- 面向公众的安装引导、更新系统、付费能力或 Mac App Store 上架准备。
- 可视化历史报表和效率仪表盘。

## 4 核心概念

### 4.1 项目

“项目”是一次可立即开始的行动入口，对应用户明确添加的一个本地资源。

支持的资源类型：

- 文件夹，例如 `~/Documents/CS61A-Assignments`。
- 视频文件。
- PDF 和 macOS 可通过默认应用打开的常见文档。

文件夹可以代表需要多次推进的长期项目。打开文件夹不代表项目完成。

### 4.2 项目状态

项目只有以下三种业务状态：

| 状态 | 是否参与抽取 | 说明 |
| --- | --- | --- |
| 进行中 | 是 | 默认状态，满足冷却和可用性条件时参与抽取 |
| 暂停 | 否 | 暂时退出行动池，可恢复为进行中 |
| 已完成 | 否 | 用户明确完成，不再参与抽取 |

删除不是项目状态。删除操作只移除应用中的项目记录，不得删除、移动或修改原始文件。

### 4.3 权重

每个项目必须具有高、中、低三个权重等级。新增项目默认使用中权重。

实现默认值：

| 权重等级 | 随机权重值 |
| --- | ---: |
| 低 | 1 |
| 中 | 2 |
| 高 | 3 |

权重只影响符合抽取条件的项目之间的相对概率。

### 4.4 冷却

项目每次被抽中并展示后，立即进入 24 小时冷却。冷却从结果生成时间开始计算，与用户是否点击“打开”无关。

冷却期间，该项目不得再次进入候选集合。重抽同样会让被放弃的结果保持冷却状态。

## 5 核心用户流程

### 5.1 首次建立行动池

1. 用户打开管理窗口。
2. 用户把文件或文件夹拖入窗口，或点击添加按钮打开系统文件选择器。
3. 应用创建项目并读取资源名称和路径。
4. 用户可以修改自定义名称、行动备注和权重。
5. 项目以“进行中”状态保存。

### 5.2 随机抽取

1. 用户点击 macOS 菜单栏图标。
2. 菜单栏面板显示“抽一个”主入口。
3. 用户点击“抽一个”。
4. 应用从当前符合条件的项目中按权重随机选择一项。
5. 应用显示结果卡片，包括自定义名称、完整路径和备注。
6. “打开”和“重抽”按钮必须同等显眼。
7. 用户点击“打开”时，应用用 macOS 默认应用打开资源。
8. 用户点击“重抽”时，应用选择另一个符合条件的项目并替换当前结果。

### 5.3 长期项目

1. 用户抽中一个文件夹项目。
2. 用户通过 Finder 打开并推进其中的工作。
3. 项目继续保持“进行中”。
4. 冷却结束后，该项目可再次被抽中。
5. 只有用户手动标记“已完成”后，该项目才永久退出抽取集合。

### 5.4 项目维护

用户必须能在管理窗口中：

- 查看所有项目。
- 新增项目。
- 修改自定义名称、备注和权重。
- 在进行中、暂停和已完成之间切换状态。
- 修复失效路径。
- 删除项目引用。

## 6 功能需求

### FR 001 菜单栏应用

- 应用必须常驻 macOS 菜单栏。
- 点击菜单栏图标必须打开轻量面板。
- 轻量面板必须支持完整的抽取、结果展示、打开和重抽流程。
- 项目管理必须在独立窗口中完成。
- 关闭管理窗口不得退出菜单栏应用。

### FR 002 添加项目

- 管理窗口必须支持拖放文件和文件夹。
- 管理窗口必须提供系统文件选择器。
- 文件选择器必须允许选择文件或文件夹。
- 应用不得递归扫描文件夹内容。
- 每次用户选择一个文件夹时，只创建一个代表该文件夹的项目。
- 添加成功后，项目默认名称取资源显示名称，默认权重为中，默认状态为进行中。

### FR 003 重复检测

- 同一资源不得创建多个项目记录。
- 应用必须基于规范化资源标识检测重复，不能只比较用户可编辑的名称。
- macOS 实现应优先使用安全作用域书签解析后的规范 URL 或等价的稳定资源标识。
- 检测到重复时，不新增项目，并在管理窗口中定位或选中已有项目。

### FR 004 项目字段

每个项目必须保存以下字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| id | UUID | 创建后不可变 |
| displayName | String | 必填，可编辑 |
| note | String | 可空，可编辑 |
| resourceType | Enum | folder video document |
| originalPath | String | 用于展示完整路径 |
| bookmarkData | Data | 持久访问本地资源 |
| status | Enum | active paused completed |
| weight | Enum | low medium high |
| createdAt | Date | 创建时间 |
| updatedAt | Date | 最近更新时间 |
| lastDrawnAt | Date | 可空 |
| cooldownUntil | Date | 可空 |
| availability | Enum | available unavailable |

### FR 005 编辑项目

- 用户必须能编辑名称、备注和权重。
- 用户必须能改变项目状态。
- 状态改为暂停或已完成后，项目必须立即退出候选集合。
- 状态从暂停或已完成改回进行中时，既有冷却时间仍然有效。
- 编辑项目不得修改原始文件的名称、位置或内容。

### FR 006 删除项目

- 删除项目前必须明确说明“只会移除应用中的记录，不会删除本地文件”。
- 确认删除后，只删除项目记录、书签数据和该项目关联的本地事件数据。
- 应用不得调用删除文件或移到废纸篓的系统操作。

### FR 007 候选集合

一个项目只有同时满足以下条件时，才能进入候选集合：

1. 状态为进行中。
2. 当前时间不早于 `cooldownUntil`，或 `cooldownUntil` 为空。
3. 安全作用域书签可以解析，且资源当前可访问。

暂停、已完成、仍在冷却或资源失效的项目不得参与抽取。

### FR 008 加权随机

- 应用必须从候选集合中按权重随机选择一项。
- 每次抽取必须独立计算候选集合，避免使用已过期状态。
- 首版使用低 1、中 2、高 3 的权重值。
- 随机实现不得让列表排序影响概率。

参考伪代码：

```text
eligible = projects.filter(isActive && cooldownExpired && resourceAvailable)

if eligible.isEmpty:
    showEmptyState()
    return

total = sum(weightValue(project.weight) for project in eligible)
ticket = randomNumber(in: 0..<total)

for project in eligible:
    ticket -= weightValue(project.weight)
    if ticket < 0:
        selected = project
        break

selected.lastDrawnAt = now
selected.cooldownUntil = now + 24 hours
save(selected)
showResult(selected)
```

### FR 009 抽取结果

结果卡片必须显示：

- 项目自定义名称。
- 项目完整路径。
- 项目备注；备注为空时不保留空白占位区域。
- “打开”按钮。
- “重抽”按钮。

结果卡片不要求显示权重、最近打开时间、统计数据或资源类型图标。

### FR 010 重抽

- 用户可以无限重抽。
- “重抽”与“打开”必须具有相同的视觉层级和可点击性。
- 重抽不需要填写原因或二次确认。
- 重抽必须从重新计算后的候选集合中选择。
- 当前结果已经进入冷却，因此不得被立即再次抽中。
- 应用不得另外提供“跳过”按钮。

### FR 011 打开资源

- 点击“打开”时，应用必须调用 macOS 系统默认处理方式。
- 文件夹必须在 Finder 中打开。
- 视频、PDF 和文档必须由对应的默认应用打开。
- 应用不得在内部预览或播放资源。
- 成功发起系统打开请求后，记录一次本地打开事件。
- 打开资源不得自动把项目标记为已完成。

### FR 012 路径失效

- 每次抽取前，应用必须验证候选资源可访问。
- 若安全作用域书签可解析到移动后的资源，应更新保存的路径和书签。
- 若资源无法访问，应把项目标记为不可用并从本次候选集合移除。
- 遇到失效项目时，应用应自动继续抽取，不把该过程计为用户重抽。
- 管理窗口必须清楚标出不可用项目，并提供“重新定位”操作。
- 用户重新选择资源后，应用必须更新路径和书签，并恢复为可用。

### FR 013 无可用项目

候选集合为空时，菜单栏面板必须显示明确原因，至少区分以下情况：

- 尚未添加任何项目。
- 所有项目均为暂停或已完成。
- 所有进行中项目仍在 24 小时冷却。
- 所有进行中项目的路径均不可用。

空状态必须提供“打开管理窗口”入口。MVP 不提供忽略冷却并强制抽取的按钮。

### FR 014 最少本地行为记录

应用必须仅在本地保存验证核心流程所需的最少数据：

- 每次用户主动开始抽取的时间。
- 一次抽取会话中的重抽次数。
- 该会话是否点击过“打开”。
- 从第一次抽取到点击“打开”的耗时；未打开时为空。

MVP 不需要向用户展示历史记录页面。数据不得上传或用于用户画像。

建议的数据结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 会话标识 |
| startedAt | Date | 第一次点击抽取的时间 |
| rerollCount | Integer | 同一面板会话中的重抽次数 |
| openedProjectId | UUID | 可空 |
| openedAt | Date | 可空 |
| timeToOpenMs | Integer | 可空 |

### FR 015 抽取会话边界

实现默认值：用户第一次点击“抽一个”时创建抽取会话。以下任一事件结束当前会话：

- 用户点击“打开”。
- 用户关闭菜单栏面板。
- 应用退出。

面板关闭后再次打开并点击“抽一个”，应创建新会话。

## 7 界面要求

### 7.1 菜单栏面板

菜单栏面板包含三种主要状态：

#### 待抽取状态

- 显示一个清晰的“抽一个”按钮。
- 提供进入管理窗口的次要入口。
- 不显示项目列表、筛选器或标签。

#### 结果状态

- 显示自定义名称、完整路径和备注。
- “打开”和“重抽”同等显眼。
- 信息应在常规菜单栏面板宽度内正常换行，不截断关键名称。

#### 空状态

- 说明没有可抽取项目的具体原因。
- 提供打开管理窗口的入口。

### 7.2 管理窗口

管理窗口至少包含：

- 项目列表。
- 添加按钮和可接收拖放的区域。
- 项目名称、路径、备注、权重、状态和可用性。
- 编辑、暂停、恢复、完成、重新定位和删除操作。

实现默认值：列表按“进行中、暂停、已完成”的顺序分组，同组内按最近更新时间倒序排列。该排序不得影响随机概率。

### 7.3 视觉原则

- 首版以清晰、原生和稳定为优先。
- 不需要自定义主题、音效或复杂动画。
- 应支持 macOS 浅色和深色外观的系统默认适配。
- 所有按钮和状态必须支持键盘焦点与 VoiceOver 可访问名称。

## 8 本地存储与权限

### 8.1 数据存储

- 项目记录、书签、冷却时间和最少行为记录必须全部保存在本机。
- 首版不得实现导入导出、云备份或网络同步。
- 存储实现可以使用 SwiftData、Core Data 或等价本地数据库；若仓库已有持久化方案，应优先复用。

### 8.2 文件访问

- 应用只允许访问用户通过拖放或系统文件选择器明确授权的资源。
- macOS 沙盒环境下必须使用安全作用域书签保存持久访问权限。
- 应用不得请求完全磁盘访问。
- 应用不得枚举未授权目录。

### 8.3 网络与隐私

- 应用功能不得依赖网络。
- 不得发送项目名称、路径、备注、文件内容或行为数据。
- 不得包含分析、崩溃上报、广告或远程配置 SDK。
- 若构建配置允许，应移除不需要的网络权限与网络依赖。

## 9 状态与事件规则

### 9.1 项目状态转换

```text
进行中 ──暂停──> 暂停
暂停 ──恢复──> 进行中
进行中 ──完成──> 已完成
暂停 ──完成──> 已完成
已完成 ──重新激活──> 进行中
```

删除操作可以作用于任意状态，但只删除应用记录。

### 9.2 可用性状态

可用性与项目业务状态相互独立。一个项目可以同时是“进行中且不可用”。不可用项目保留在管理窗口中，但不参与抽取。

### 9.3 冷却规则

- 进入冷却：结果成功生成并展示。
- 冷却时长：连续 24 小时。
- 暂停或完成：不清除冷却时间。
- 重新激活：若冷却尚未结束，继续等待。
- 修改权重、名称或备注：不改变冷却时间。
- 修复失效路径：不改变冷却时间。

## 10 异常与边界条件

| 场景 | 预期行为 |
| --- | --- |
| 用户拖入不支持或无法打开的项目 | 拒绝添加并给出简短原因 |
| 用户重复添加同一资源 | 不新增，定位已有项目 |
| 项目在添加后被移动 | 尝试通过书签解析新位置并更新路径 |
| 项目被删除或磁盘未挂载 | 标记不可用，自动继续抽取 |
| 候选仅剩一个项目 | 正常抽中并进入冷却；之后显示无可用项目 |
| 用户连续快速点击抽取或重抽 | 必须串行处理，不能生成并发结果或重复记录 |
| 用户点击打开但系统调用失败 | 显示失败提示，不标记完成；保留当前结果 |
| 用户在结果展示期间暂停或删除该项目 | 关闭或刷新当前结果，不允许继续打开失效引用 |
| 系统时间发生较大变化 | 使用绝对日期重新判断冷却，不产生负时长 |
| 应用意外退出 | 已保存的项目、冷却和状态必须保留 |

## 11 非功能要求

### NFR 001 启动速度

- 菜单栏面板应在点击图标后立即出现。
- 对 15 至 30 个项目的典型个人数据集，随机结果应在用户点击后无感知延迟地出现。

### NFR 002 可靠性

- 项目状态、冷却时间和书签更新必须持久化。
- 抽取操作必须避免重复写入和并发状态竞争。
- 单个失效项目不得中断整个抽取流程。

### NFR 003 可访问性

- 所有交互控件必须有明确的 VoiceOver 标签。
- 键盘用户必须能完成抽取、重抽、打开和基本项目管理。
- 界面不得只依赖颜色表达权重、状态或错误。

### NFR 004 平台

实现默认值：使用原生 Swift 和 SwiftUI 开发，最低支持 macOS 14。需要 AppKit 能力时可以局部桥接，但不得为此引入跨平台框架。

## 12 验收标准

### AC 001 添加与持久化

在添加一个文件、一个视频和一个文件夹并重启应用后，三个项目仍存在，名称、备注、权重和状态保持不变。

### AC 002 文件夹粒度

添加 `CS61A-Assignments` 文件夹时，应用只创建一个项目，不扫描或创建其中的子文件项目。

### AC 003 加权随机

在固定测试随机种子和已知项目集合下，抽取逻辑必须严格遵循低 1、中 2、高 3 的相对权重，并且不受列表排序影响。

### AC 004 冷却

项目一旦显示为结果，`cooldownUntil` 必须设为结果时间后的 24 小时；在该时间前不得再次进入候选集合。

### AC 005 无限重抽

只要仍有符合条件的项目，用户可以连续重抽，不需要理由或确认；已展示项目不得在冷却期内再次出现。

### AC 006 系统打开

文件夹由 Finder 打开，视频、PDF 和文档由系统默认应用打开。打开后项目仍为进行中。

### AC 007 状态过滤

暂停和已完成项目不会被抽中；恢复为进行中后，在冷却已结束且资源可用的条件下可以再次被抽中。

### AC 008 失效路径

当候选项目路径失效时，应用标记该项目不可用并自动尝试其他候选项。管理窗口提供重新定位能力。

### AC 009 安全删除

从应用中删除项目后，本地原始文件仍完整存在。

### AC 010 隐私

在无网络环境中，除首次构建或系统自身行为外，应用全部核心功能可正常使用；代码中不存在遥测或第三方分析调用。

### AC 011 最少行为记录

每次抽取会话能够本地记录开始时间、重抽次数、是否打开和打开耗时，但界面中不需要展示统计页面。

### AC 012 空状态

没有候选项时，应用不会崩溃或绕过冷却，并能说明原因及提供管理入口。

## 13 测试要求

AI 开发代理至少应覆盖以下自动化测试：

- 候选集合过滤测试。
- 三档权重映射测试。
- 加权抽取边界测试。
- 24 小时冷却开始、未到期和到期测试。
- 项目状态转换测试。
- 重复资源识别测试。
- 路径失效后的回退测试。
- 抽取与重抽并发保护测试。
- 删除记录但保留原文件的测试。
- 抽取会话计数和耗时计算测试。

至少进行以下人工测试：

- 拖入文件、视频和文件夹。
- 通过文件选择器添加资源。
- 重启应用后验证书签访问。
- 移动文件后验证书签解析或重新定位。
- 断开外接磁盘后验证失效状态。
- 使用菜单栏完成抽取、重抽和打开。
- 使用键盘和 VoiceOver 完成核心流程。
- 在浅色与深色外观下检查界面。

## 14 MVP 完成定义

只有同时满足以下条件，MVP 才算完成：

1. 用户可以建立并维护由本地资源组成的行动池。
2. 菜单栏中的抽取、结果、重抽和打开形成完整闭环。
3. 加权随机、24 小时冷却和三种项目状态按本文工作。
4. 失效路径不会阻断抽取，且可在管理窗口修复。
5. 删除项目不会影响原始文件。
6. 所有数据留在本机，应用不依赖网络。
7. 核心逻辑具有自动化测试，主要用户流程经过人工验证。

## 15 自用验证建议

本节用于产品验证，不阻塞 MVP 开发或发布。

- 添加 15 至 30 个真实项目。
- 在空档、走神或不知道下一步做什么时使用应用。
- 连续使用两周。
- 观察自己是否愿意持续使用，以及随机候选是否帮助自己更快开始。
- 若经常连续重抽，优先研究“当下时间、精力或工作场景是否需要轻量约束”，不要直接加入 AI 推荐或复杂筛选。

## 16 AI 实现顺序

建议按以下顺序实现，每一步都应保持项目可运行：

1. 建立项目数据模型和本地持久化。
2. 实现文件选择、拖放、安全作用域书签和重复检测。
3. 实现项目列表、编辑、状态切换和删除引用。
4. 实现候选过滤、权重随机和 24 小时冷却。
5. 实现菜单栏面板、结果卡片、无限重抽和系统打开。
6. 实现路径失效检测、自动回退和重新定位。
7. 实现最少本地行为记录。
8. 补齐自动化测试、键盘操作、VoiceOver 标签和异常处理。
9. 完成个人安装构建并按验收标准逐项验证。
